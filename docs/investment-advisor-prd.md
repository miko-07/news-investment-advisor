# 产品需求文档：每日新闻投资参考系统

**版本**: 1.0  
**日期**: 2026-05-03  
**状态**: 已上线  

---

## 一、执行摘要

本系统是一个自动化财经新闻分析与推送平台，每日定时抓取国内外财经新闻，通过 DeepSeek AI 进行深度分析，生成结构化的投资参考报告，并通过邮件推送给用户。系统包含两条独立流水线：**早间晨报**（盘前策略）和**收盘复盘**（盘后回顾），覆盖 A 股交易日完整的信息服务闭环。

目标用户为有一定投资经验的个人投资者，需要每日获取结构化的市场信息汇总和 actionable 的投资建议，但缺乏时间和专业能力自行跟踪海量资讯。

---

## 二、问题背景与解决目标

### 痛点分析

| 痛点 | 说明 |
|------|------|
| 信息过载 | 国内外财经信源众多（财联社、新浪、36氪、日经、Yahoo Finance 等），个人无法在开盘前高效完成信息筛选 |
| 缺乏结构化分析 | 零散新闻难以形成投资决策，需要专业视角的梳理和解读 |
| 盘后复盘需求 | 收盘后需要快速回顾当日市场核心变量，对比盘前预期，修正次日策略 |
| 时效性要求 | 必须在开盘前（7:00）和收盘后（15:10）准时送达 |

### 解决目标

1. **早间晨报**：开盘前提供市场情绪判断、关键新闻解读、板块机会、风险预警、策略建议和推荐股票池
2. **收盘复盘**：收盘后复盘当日市场走势，识别核心催化剂，对比预期差，给出次日观察点和策略修正
3. **全自动化**：从抓取到分析到推送全程无人值守，通过 macOS launchd 定时执行

## 四、用户画像

### 核心用户：个人投资者

- **角色**：有 1-5 年投资经验的个人股票/基金投资者
- **目标**：每日快速获取市场全景和投资方向

- **技术能力**：仅需会使用邮箱接收报告，零配置要求

## 五、功能需求

### 5.1 新闻抓取模块

**ID**: FR-FETCH-001  
**优先级**: P0  
**描述**: 从 11 个国内外财经信源并行抓取新闻，去重、过滤、截断

**工作流**:
1. 读取 `config.py:NEWS_SOURCES` 中的源配置
2. 4 线程并行池抓取，每个源独立超时
3. 按标题前 15 字去重
4. 过滤超过 24 小时的旧闻
5. 截断至最多 50 篇，按发布时间倒序

**支持的信源类型**:
| 类型 | 解析方式 | 示例源 |
|------|---------|--------|
| `rss` | feedparser | 36氪、日经中文网、Yahoo Finance、BBC中文 |
| `json` | 域名映射解析器 | 财联社 CLS API、新浪财经（4 路） |

**出错处理**:
- 单个源超时/报错不阻塞整体，仅跳过
- SSL 错误自动重试 3 次（1s+ jitter）
- 国内源 10s 超时，国外源 8s 超时（VPN 断开时快速失败）

**验收标准**:
- [ ] 11 个源均能独立成功抓取
- [ ] 去重后 ≥ 5 篇方可进入下一阶段
- [ ] 任一源失败不影响其他源

### 5.2 AI 分析模块（早报）

**ID**: FR-ANALYZE-MORNING  
**优先级**: P0  
**描述**: 调用 DeepSeek API 对新闻进行结构化分析，生成 6 节 Markdown 报告

**System Prompt 设计**:
- 角色：资深宏观策略分析师
- 风格：简洁有力、多空分明、具体到板块
- 约束：不编造具体价格、目标价、止损价
- 标题：40 字内，使用数字/对比/疑问手法制造点击欲望

**输出结构**:
| 章节 | 内容 | 格式 |
|------|------|------|
| 一、市场情绪速览 | 3-5 句全局判断 + 多空倾向 | 纯文本 |
| 二、关键新闻解读 | 5-8 条最重要新闻逐条分析 | 标题 + 影响分析 + 操作建议 |
| 三、板块与品种机会 | A股/美股港股/债券/商品外汇 | 分维度列表 |
| 四、风险预警 | 3-5 个风险点，按重要性排序 | 序号列表 + 危害说明 |
| 五、今日策略 | 一句话核心策略 + 3 条操作建议 | 带适用人群标注 |
| 六、推荐股票池 | 3-5 只股票 | 名称/代码/推荐理由 三列表格 |

**出错处理**: 3 次重试，指数退避（1s, 2s, 4s）

**验收标准**:
- [ ] 输出严格遵循 6 节 Markdown 结构
- [ ] 不出现虚构的价格/目标价
- [ ] 每节内容非空

### 5.3 实时行情增强模块

**ID**: FR-ENRICH  
**优先级**: P1  
**描述**: 从早报推荐股票池提取股票代码，拉取实时行情和近期走势，追加买卖策略

**工作流**:
1. `extract_stock_codes()` 从 Markdown 表格中提取股票代码
2. `codes_to_sina()` 转换为新浪行情 API 格式
3. `fetch_prices()` 获取实时报价
4. `fetch_daily_trends()` + `compute_trend_summary()` 获取 5 日 K 线并计算支撑/阻力
5. `enrich_with_prices()` 调用 DeepSeek 生成第七节买卖策略

**输出**: 追加 `## 七、买卖策略参考`，包含每只股票的买入区间、止损价、目标价、仓位、催化剂

**出错处理**:
- 行情获取失败 → 跳过增强，保留原报告
- API 调用失败 → 跳过，保留原报告
- 所有失败仅 warning，不终止流水线

**验收标准**:
- [ ] 推荐股票池中的代码能被正确提取
- [ ] 行情获取成功时追加七、买卖策略参考
- [ ] 行情获取失败时不影响早报本身

### 5.4 收盘复盘模块

**ID**: FR-ANALYZE-REVIEW  
**优先级**: P0  
**描述**: 收盘后（交易日 15:10）对当日市场进行复盘分析

**输入数据源**:
1. **新闻内容**：当日最新新闻（含收盘报道）
2. **实时行情快照**：6 个主要指数的精确收盘点位（上证指数、深证成指、创业板指、上证50、沪深300、科创50），通过 `fetch_market_snapshot()` 爬取
3. **早报上下文**（可选）：当日早报前 4 章，用于"预期对比"分析

**System Prompt 设计**:
- 角色：交易总监视角的复盘分析师
- 核心关注点："预期差"——市场实际走势 vs 早盘预期
- 数据完整性规则：所有价格、涨跌幅必须来自提供的行情数据，不得编造

**输出结构**:
| 章节 | 内容 |
|------|------|
| 一、今日市场复盘 | 4-6 句总结：指数表现、成交量、资金流向、超预期事件 |
| 二、核心催化剂回顾 | 4-6 条关键信号 + 实际影响 + 预期对比 |
| 三、板块轮动与资金特征 | 领涨/领跌板块 + 资金行为特征 |
| 四、今日市场异动观察 | 3-5 个异动信号 |
| 五、明日关键观察点 | 3-5 个观察信号 + 意义 + 应对 |
| 六、持仓策略修正 | 判断维持/修正 + 理由 |

**验收标准**:
- [ ] 仅在工作日执行（`chinese_calendar` 判断节假日）
- [ ] 早报存在时，"预期对比"引用早报具体判断
- [ ] 行情快照成功时，引用精确点位
- [ ] 指数点位必须来自实际爬取数据，不编造

### 5.5 格式化模块

**ID**: FR-FORMAT  
**优先级**: P0  
**描述**: 将 Markdown 分析报告转换为微信公众号兼容的 HTML

**功能列表**:
- 支持 h1-h3 标题（带内联 CSS 样式）
- 加粗/斜体、行内代码、代码块
- 无序/有序列表（含多行项缩进延续）
- 引用块、水平分割线、超链接
- Markdown 表格（带交替行色）
- 转义字符处理（`\*` → `*`）

**样式要求**:
- 主色调 #c0392b（深红色）
- 移动端适配，max-width 680px
- 邮件客户端兼容（inline CSS）
- 微信公众号编辑器兼容（可直接粘贴）

**验收标准**:
- [ ] Markdown 全部元素正确转换
- [ ] 在主流邮件客户端（QQ邮箱、163、Gmail）中渲染正常
- [ ] 可粘贴至微信公众号编辑器

### 5.6 邮件发送模块

**ID**: FR-EMAIL  
**优先级**: P0  
**描述**: 通过 SMTP 发送 HTML 邮件，附带 Markdown 源文件附件

**配置参数**:
- SMTP 服务器、端口（默认 465 SSL）、账号、授权码
- 收件人地址
- 均通过 `.env` 配置，不写死在代码中

**功能**:
- HTML 正文
- 纯文本降级（BeautifulSoup 提取前 2000 字）
- `.md` 文件作为 `text/markdown` MIME 附件
- 邮件主题：早报 `📊 {标题}`，复盘 `📋 复盘 | {标题}`

**验收标准**:
- [ ] 各类邮箱均能正确接收
- [ ] 附件可下载，内容完整
- [ ] 发送失败有明确错误日志（鉴权失败、SMTP 异常等）

### 5.7 定时调度模块

**ID**: FR-SCHEDULE  
**优先级**: P0  
**描述**: 通过 macOS launchd 定时执行两条流水线

| 流水线 | 计划 | 管理命令 |
|--------|------|---------|
| 早报 | 每天 7:00 | `launchctl start com.news.investment-advisor` |
| 复盘 | 交易日 15:10（周一至五） | `launchctl start com.news.investment-advisor.review` |

**设计选择**:
- 使用 launchd 而非 cron：电脑睡眠唤醒后自动补执行错过的任务，cron 静默跳过

**运行时检查**:
- 复盘流水线额外检查 `chinese_calendar.is_workday()`，跳过法定节假日

**验收标准**:
- [ ] 早报在 7:00 ± 1 分钟内触发
- [ ] 复盘在交易日 15:10 ± 1 分钟内触发
- [ ] 节假日自动跳过
- [ ] 睡眠恢复后补执行

### 5.8 历史报告查看器

**ID**: FR-VIEWER  
**优先级**: P1  
**描述**: Flask Web 应用，可视化浏览历史报告

**功能**:
| 路由 | 功能 |
|------|------|
| `/` | 卡片列表，显示日期、标题、多空标签（偏多/偏空/震荡）、报告类型（定时/测试/复盘） |
| `/report/<filename>` | 全文展示，优先使用预生成 HTML |

**安全**: `Path.resolve()` 路径穿越防护

**验收标准**:
- [ ] 支持 `analysis_*`、`review_*`、`test_analysis_*` 三种文件前缀
- [ ] 静态资源无需额外加载

## 六、技术架构

### 整体流程

```
早报流水线（4 步）:
  news_fetcher.fetch_all_news()
  → analyzer.analyze_news()
  → price_fetcher.* + analyzer.enrich_with_prices()  [行情增强，失败跳过]
  → formatter.markdown_to_wechat_html()
  → email_sender.send_email()

复盘流水线（3 步）:
  news_fetcher.fetch_all_news()
  → price_fetcher.fetch_market_snapshot()  [注入行情]
  → analyzer.analyze_closing_review(早报上下文, 行情快照)
  → formatter.markdown_to_wechat_html()
  → email_sender.send_email()
```

### 模块关系

| 模块 | 职责 | 外部依赖 |
|------|------|---------|
| `config.py` | 集中配置 | python-dotenv |
| `news_fetcher.py` | 多源并行新闻抓取 | feedparser, requests, BeautifulSoup |
| `analyzer.py` | DeepSeek 三阶段分析 | openai (SDK) |
| `price_fetcher.py` | 实时行情/趋势爬取 | requests |
| `formatter.py` | Markdown → 微信 HTML | 自实现 |
| `email_sender.py` | SMTP 邮件发送 | smtplib, MIME |
| `main.py` | 流水线编排、CLI、launchd | argparse, logging |
| `viewer.py` | Flask 历史查看 | Flask |

### 数据结构

```python
# 核心文章字典
article = {
    "title": str,
    "source": str,          # 信源名称
    "url": str,             # 原文链接
    "summary": str,         # 摘要（300 字截断）
    "published": datetime | None,  # 时区感知
}
```

### 缓存策略

| 文件 | 用途 | 前缀 |
|------|------|------|
| `output/analysis_YYYYMMDD.md` | 早报 Markdown | `analysis_` |
| `output/analysis_YYYYMMDD.html` | 早报 HTML | `analysis_` |
| `output/review_YYYYMMDD.md` | 复盘 Markdown | `review_` |
| `output/review_YYYYMMDD.html` | 复盘 HTML | `review_` |

执行时先检查 HTML 是否已存在，存在则复用（re-send only）。  
复盘和早报使用独立前缀，互不干扰。

## 七、非功能需求

### 性能
- 单次流水线执行时间 < 3 分钟（含 DeepSeek API 请求时间）
- Promise（4 线程）并行抓取
- 日志自动轮转，5MB 上限，3 份备份

### 安全
- API Key 和 SMTP 凭据仅存在 `.env` 文件，不提交至版本控制
- Viewer 使用 `Path.resolve()` 防止目录穿越
- 无外部网络监听端口（仅 viewer 开发时监听 localhost:8899）

### 可靠性与容错
- DeepSeek API 调用：3 次重试，指数退避
- 新闻获取：线程池隔离，单源失败不阻塞整体
- 国外新闻源：8s 超时，VPN 断开时快速失败
- 行情增强：失败跳过，不阻塞流水线
- 总新闻数 < 5 篇时终止执行

### 可维护性
- 所有可调参数集中在 `config.py`
- 信源增删改仅需修改 `config.py:NEWS_SOURCES`
- 新增 JSON 信源需在 `_JSON_PARSERS` 注册解析函数

## 九、风险与缓解

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|---------|
| DeepSeek API 不稳定/限流 | 低 | 高 — 当天无报告 | 3 次重试 + 错误日志告警 |
| 新闻源 API 变更/失效 | 中 | 中 — 某源不可用 | 多源冗余（≥11），单源失效不影响整体 |
| 国内 CDN SSL 握手失败 | 中 | 低 — 部分源失败 | HTTP/1.1 ALPN 固定 + 3 次 SSL 重试 |
| 用户邮箱收不到邮件 | 低 | 中 | SMTP 日志可查；HTML+MD 文件保留在 output/ |
| macOS 版本升级导致 launchd 变更 | 低 | 中 | plist 文件保留，可手动重新安装 |
